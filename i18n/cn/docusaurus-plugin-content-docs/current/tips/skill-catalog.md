# 技能目录

技能是 Aeven 每次都按同样方式执行的流程。**设置 → 技能** 里的 **技能目录** 收录了约一百个随 Aeven 提供的现成技能。开启一个，它就加入你的技能库；之后任务需要时 Aeven 会用它，你也可以输入 `/` 加上它的名字自己启动。[技能](../using/skills.md)

日常工作不需要目录——不用它，Aeven 也能写作、读文档、搜索和构建。目录里的技能是在此之上加一套专家方法：一份检查清单、一种固定风格、一组把某件事做得特别好的脚本。

## 写作

| 技能 | 用它来 |
| --- | --- |
| **humanizer** | 把听起来像机器写的文字改写得像你写的，不改变它要说的内容。对草稿、邮件、帖子说一句*“humanize 一下”* |
| **content-creator** | 用一致的品牌语气写营销内容，带 SEO 和社交媒体格式 |
| **marketing-strategy-pmm** | 定位、发布计划、理想客户画像和竞品分析 |
| **seoagent** | 网站的技术 SEO 审查、关键词规划和内容简报 |

## 弄清软件是怎么工作的

| 技能 | 用它来 |
| --- | --- |
| **reverse-engineering** | 从已发布的软件本身弄清一个应用做了什么：桌面和手机应用、网页包、固件、数据库、网络抓包 |
| **leanrea** | 同样的事，只用普通命令行工具，适合快速看一眼某个二进制文件或应用包 |

请用于你拥有或获准检查的软件——查看某个应用发送了什么、恢复丢失的文件格式，或弄懂一个没有文档的工具。

## 开发者工作流

**aeven-stack** 这一组——约三十个名字以 `avn-` 开头的技能——给开发者一整套工作方法：规划改动、先写测试、审查、开启并跟进拉取请求、发布。按名字启动：`/avn-pr` 提交一个拉取请求，`/avn-review-loop` 让一位全新的审查者反复审查改动直到双方都认为没问题，`/avn-ship` 把改动一路推进到合并的拉取请求。`/aeven-stack` 会告诉你哪一个适合手头的工作。

## 诀窍

- **只开启你会用的。**技能库里的每个技能都是 Aeven 要多考虑的一样东西；技能库短，选得更快。
- **按名字启动**：想要某个确切的方法时用 `/`，例如 `/humanizer`。
- **让模型来启动**：保持 **模型可自行调用此技能** 开启，任务合适时 Aeven 就会用上它。
- **先看看里面。**每个技能的页面都会显示它带来的说明和文件。
- **带上你自己的。**任何按相同 `SKILL.md` 结构存放技能的仓库都可以导入。[技能](../using/skills.md#导入你自己的)
