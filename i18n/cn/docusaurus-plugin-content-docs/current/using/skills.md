# 技能

技能是一份写下来的流程：一件你常做的事的步骤，连着它要用的说明和文件。教 Aeven 一次，下次它就用同一种方式跑，不用你再一次解释格式、顺序和例外。

技能讲的是“怎么做”。[bot](../automation/automations.md) 讲的是“它什么时候自己跑”。一个要用某个账号的技能，需要那个账号先[连上](../connections/connected-apps.md)。

## 它们在哪儿

**Settings → Skills** 有两个视图：**Skills**，你有的那些；**Catalog**，Aeven 自带的那些。在消息框里输入 `/`，就能看到有哪些可以按名字启动。

内置技能随 Aeven 一起来，一直都在。它们刻意不进你的列表，因为没有什么可以关掉。

## 跟着连接器一起来的技能

大多数连接器带来自己的技能：Gmail 的知道怎么搜邮件、怎么起草，Drive 的懂 Docs、Sheets、Slides 和评论，GitHub 的懂仓库、议题和拉取请求，聊天类的连接器懂它自己那套工具。它们出现在连接器的详情里，跟着连接器一起打开，不能单独启用——断开连接器，它们就走了。有些连接器直接露出自己的工具、不带成套的流程，这种会在它的页面上说明。

目录里也放着为一般工作写的技能。搜一搜，看看某个技能被装了多少次，把你要的打开；打开了的目录技能会进你的库。

## 导入你自己的

**Settings → Skills → Import skill** 接受：

- 一个 GitHub URL、一个 npm 包，或者 `owner/repository` 这样的简写——Aeven 会下载那个压缩包，把它带着的每个技能都导进来；
- 一个文件：一个 `SKILL.md`、一个 `.skill` 包，或者里面正好只有一个技能的 ZIP。

只导入你信得过的技能。技能是 Aeven 会拿着你的工具、在你的文件上照着做的说明，所以应用会让你确认要引进来的是什么。

导入之后，结果会告诉你来了什么：

| 它说 | 发生了什么 |
| --- | --- |
| Added | 你的库里多了一个新技能 |
| Kept built in | Aeven 已经用自带的或者更早的技能回应这个名字了；这次导入没有替换它 |
| Some referenced files were not in the repository | 这个技能到了，但它点名的文件没到；它照样能用已经到的那些跑 |

## 由另一个 agent 装的技能

如果这台电脑上装了 Claude Code 或 Codex，**Settings → Skills** 会列出它在那儿找到的技能，按 agent 分组。打开一个，就把它复制进你的库；关掉，就删掉你那份，另一个 agent 的文件夹原样不动。只有当打开真的能装上时，一个技能才会出现在这里。

## 谁能启动一个技能

| 谁启动的 | 什么时候 |
| --- | --- |
| 你，输入 `/name` | 总是可以，你库里的每个技能都行 |
| 模型，当它认出这件事的时候 | 只在这个技能的 **Model can start this skill** 打开的时候 |

导入时会拿技能自己的设置当它的初始值，所以一个要求不要被自动启动的技能，导入后还是那样。对代价大的事，或者一个你想自己带头的流程，关掉它是对的。

## 看看里面

打开一个技能，能看到它的 **Source**、它包里的文件，还有它的引用。这是“它到底会做什么”的诚实答案——在网上找到的东西，打开之前先读一读。

## 当一个技能需要一个程序

有些技能靠你电脑上的软件。第一次用一个的时候，Aeven 会装上它需要的东西，并把进度显示出来；如果失败，它会说是哪一步没成，并在技能的页面上提出再试一次。这期间对话的其余部分照常往下走。

## 删掉一个

**Remove skill** 删掉你导入的技能的副本，改动从下一条消息起生效。内置技能删不掉，连接器的技能跟着连接器一起走。
